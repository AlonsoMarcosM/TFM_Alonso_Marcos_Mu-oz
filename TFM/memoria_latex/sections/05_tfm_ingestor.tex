\section{Automatización de gobierno con \texttt{om\_dcat\_sync}}

El componente \texttt{om\_dcat\_sync} (alias legacy \texttt{tfm\_ingestor}) es el núcleo backend del caso de uso. Centraliza descubrimiento, planificación, aplicación de gobierno, exportación DCAT-AP-ES y validación SHACL para que CLI, scripts y app web no dupliquen reglas.

Reglas idempotentes aplicadas:
\begin{itemize}
  \item esquema $\rightarrow$ capa (\texttt{bronze/silver/gold}),
  \item esquema $\rightarrow$ domain,
  \item prefijo de tabla $\rightarrow$ tags de tema/keyword,
  \item custom properties mínimas para perfil obligatorio DCAT-AP-ES.
\end{itemize}

Capacidades implementadas:
\begin{itemize}
  \item configuración externa en YAML,
  \item cliente REST de OpenMetadata,
  \item dry-run para inspección previa,
  \item workflow canónico sobre activos PostgreSQL ingeridos en OpenMetadata,
  \item exportación JSON-LD de metadatos con clases activas DCAT-AP-ES/HVD,
  \item validación SHACL con shapes locales congeladas.
\end{itemize}

Orden funcional:
\begin{enumerate}
  \item primero ingesta técnica en OpenMetadata,
  \item después curación funcional de \texttt{gold\_governance.csv},
  \item luego enriquecimiento de gobierno en OpenMetadata,
  \item finalmente exportación interoperable y validación.
\end{enumerate}

La app web es un frontend operativo sobre este backend. Sus botones invocan una lista cerrada de scripts PowerShell o comandos \texttt{python -m om\_dcat\_sync}; no hablan directamente con OpenMetadata ni permiten comandos arbitrarios. Cada ejecución se persiste como job y muestra log, duración, código de salida, resumen JSON y artefactos generados.

Desde el punto de vista de negocio, el operador no necesita conocer los endpoints de OpenMetadata. Revisa los datasets \texttt{gold}, completa los metadatos funcionales y lanza el workflow. Por detrás, el sistema crea o actualiza el catálogo UCLM gobernado y exporta RDF serializado en JSON-LD.
